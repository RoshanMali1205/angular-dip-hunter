## Why AMK

Coding agents are strongest when each role has a narrow job and a clear handoff. AMK turns feature work into a scoped pipeline:

| Gap in a single chat agent | What AMK adds |
|----------------------------|---------------|
| Plans and code mixed together | Dedicated **planner** before edits |
| UI polish buried in business logic | Separate **ui-styling** lane |
| Tests as an afterthought | **Vitest** generator + fixer stages |
| “Looks good” with no critique | Severity-ranked **reviewer** |
| US-market assumptions in an India app | **nse-bse-finance-buddy** specialist |

Compatible with **GitHub Copilot** custom agents, **Claude Code** subagents, and any tool that reads root `AGENTS.md`.

## Delivery pipeline

![Delivery pipeline](assets/amk-pipeline.svg)

Default flow (orchestrator-managed):

1. **Plan** — impact analysis, subtasks, acceptance criteria  
2. **Implement** — TypeScript / templates / services  
3. **Style** (when needed) — HTML/CSS responsive polish  
4. **Generate tests** — Vitest + Angular TestBed specs  
5. **Fix tests** — mocks, async, coverage gaps  
6. **Review** — severity-ranked findings; loop back if critical

## Agents

![Agent roles](assets/amk-roles.svg)

| Agent | Role |
|-------|------|
| `angular-orchestrator` | Coordinates the full pipeline; does not write code |
| `angular-planner` | Breakdown, risks, acceptance criteria, test strategy |
| `angular-implementer` | Feature implementation aligned with repo patterns |
| `angular-ui-styling` | Templates, CSS, responsive and visual polish |
| `angular-unit-test-generator` | Create Vitest specs for new/changed code |
| `angular-test-fixer` | Repair failing specs; improve coverage |
| `angular-reviewer` | Quality / bug / performance review report |
| `nse-bse-finance-buddy` | NSE/BSE market structure + Finance Buddy knowledge pack |

Canonical definitions live in [`agents/`](agents/). Tool-specific copies are generated by the sync script.

## Compatibility

![Compatibility surfaces](assets/amk-compatibility.svg)

| Surface | Path | Tool |
|---------|------|------|
| Canonical | `angular-multi-agent-kit/agents/*.md` | Source of truth |
| GitHub Copilot | `.github/agents/*.agent.md` + `.github/copilot-instructions.md` | Copilot Chat agents |
| Claude Code | `.claude/agents/*.md` + `.claude/CLAUDE.md` | Claude Code subagents |
| Shared | `AGENTS.md` | Cursor, Codex, Gemini CLI, and other AGENTS.md readers |

### Claude Code

Open the repo in Claude Code. Subagents under `.claude/agents/` are discovered automatically. Project guidance is in `.claude/CLAUDE.md`.

### GitHub Copilot

Use the agent picker in Copilot Chat (VS Code / Visual Studio). Agents are loaded from `.github/agents/*.agent.md`. Shared instructions live in `.github/copilot-instructions.md`.

## Sync

After editing files under `angular-multi-agent-kit/agents/`, regenerate tool copies:

```bash
npm run amk:sync
```

This writes:

- `.claude/agents/<name>.md`
- `.github/agents/<name>.agent.md`

Do not hand-edit the generated copies; change the canonical files and sync again.
